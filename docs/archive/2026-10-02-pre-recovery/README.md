# FPL forecasting model + MILP squad optimizer

Originally a Master's thesis (LSTM forecasting in R + MILP squad selection in Python),
since rewritten into a single Python pipeline that can be run weekly in season while
staying methodologically reproducible.

## Layout
- **fpl/**: the entire active pipeline.
  - `config.py` — paths, season parameters, and production constants (solver, weight strategy, FT policy).
  - `data/fetch.py` — fetches and cleans FPL data from vaastav's GitHub archive (dynamic season/GW discovery, no hardcoded seasons).
  - `features.py` — leakage-guarded rolling form features per player (replaces the LSTM's learned embeddings).
  - `model/` — per-position models (GK/DEF/MID/FWD): production and research-expert registry (`models.py`), training + combination bake-off (`train.py`), opt-in specialist policy/tournament/promotion tools, walk-forward and origin-based backtest predictions (`predict.py`), Optuna tuning (`tuning.py`), and probabilistic views.
  - `milp/optimize.py` — consolidated MILP squad selection (budget, formation, captain, transfers, chips), Kristiansen et al. formulation; `milp/compare_backtests.py` puts a bootstrap CI on backtest comparisons.
  - `run_week.py` — weekly driver: refresh data → retrain → pull upcoming fixtures/squad from the official FPL API → optimize transfers/lineup/captain.
- **Datasett/**: raw data and `master_dataset.csv` (generated by `fpl/data/fetch.py`).
- **legacy/baseline_outputs/**: the old LSTM's validation predictions, kept solely as the fixed benchmark `fpl/model/train.py` compares against. (The R/LSTM code and original MILP scripts were deleted — see git history.)

## Usage
```
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

python -m fpl.data.fetch          # build/update master_dataset.csv
python -m fpl.model.train         # compare models + evaluate vs the old LSTM benchmark

python -m fpl.run_week --team-id <your FPL team ID> --horizon 3
```
Without `--team-id`, `run_week.py` produces a build-from-scratch recommendation instead of
continuing an existing team. See `CLAUDE.md` for the full command reference, gameweek-numbering
convention, and the research/backtesting protocol.

## Position-specialist research interface

Production remains `single:catboost` at all four positions. The `--expert-map` and
`--mid-gate-config` interfaces are opt-in research paths; an expert map must name every position,
so an experiment cannot silently fall back to production for an omitted one. For example:

```
python -m fpl.model.predict --start-gw 153 --end-gw 183 \
  --expert-map GK=catboost,DEF=lightgbm,MID=tabm,FWD=catboost --output <predictions.csv>
```

`python -m fpl.model.moe_tournament --artifact-dir <dir>` writes an inspectable, season-aware workflow:
selection-stage tuning capped at the discovery cutoff -> fail-closed hashed tuned-artifact manifest ->
causal OOF selection and frozen champions -> frozen finalist/control artifacts -> artifact-bound promotion.
The current derived windows are GW<=136 discovery, GW137-152 selection, and GW153-183 final evaluation;
all stages structurally reject the spent GW191-221 window. Promotion uses block-bootstrap intervals for
realized-point uncertainty and exact paired one-sided sign-test p-values (ties dropped), Holm-adjusted
across at most the position map and optional MID gate. Bootstrap probabilities are not null p-values.
Production remains `single:catboost`: methodology PASS is synthetic/audit readiness only, not a real
tournament, tuned-artifact, backtest, or promotion result.

RealMLP, TabM, and TabR are optional PyTabKit research experts, not production dependencies. On macOS
arm64/Python 3.14.6 with PyTabKit 1.7.3, RealMLP completed CPU fit/predict in 13.08s (`n_epochs=1`,
seed 17) with finite predictions; TabM completed in 1.41s with same-seed max_abs_diff=0.0.
`faiss-cpu==1.15.0` installs via pip. TabR requires `skorch==1.4.0`, reached epoch-0 validation,
but produced no prediction in the bounded run: it remains unavailable/incomplete, with no substitution.
The MID gate uses only deadline-known `mins60_rate_roll5`, a training-only MASE scale, and validated
causal OOF provenance.
