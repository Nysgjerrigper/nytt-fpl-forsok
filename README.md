# FPL forecasting model + MILP squad optimizer

Originally a Master's thesis (LSTM forecasting in R + MILP squad selection in Python),
since rewritten into a single Python pipeline that can be run weekly in season while
staying methodologically reproducible.

## Layout
- **fpl/**: the entire active pipeline.
  - `config.py` — paths, season parameters, and production constants (solver, weight strategy, FT policy).
  - `data/fetch.py` — fetches and cleans FPL data from vaastav's GitHub archive (dynamic season/GW discovery, no hardcoded seasons).
  - `features.py` — leakage-guarded rolling form features per player (replaces the LSTM's learned embeddings).
  - `model/` — per-position models (GK/DEF/MID/FWD): registry (`models.py`), training + combination bake-off (`train.py`), walk-forward and origin-based backtest predictions (`predict.py`), Optuna tuning (`tuning.py`), probabilistic views (`probabilistic.py`, `probabilistic_buckets.py`).
  - `milp/optimize.py` — consolidated MILP squad selection (budget, formation, captain, transfers, chips), Kristiansen et al. formulation; `milp/compare_backtests.py` puts a bootstrap CI on backtest comparisons.
  - `run_week.py` — weekly driver: refresh data → retrain → pull upcoming fixtures/squad from the official FPL API → optimize transfers/lineup/captain.
- **Datasett/**: raw data and `master_dataset.csv` (generated by `fpl/data/fetch.py`).
- **legacy/baseline_outputs/**: the old LSTM's validation predictions, kept solely as the fixed benchmark `fpl/model/train.py` compares against. (The R/LSTM code and original MILP scripts were deleted — see git history.)

## Usage
```
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

python -m fpl.data.fetch          # build/update master_dataset.csv
python -m fpl.model.train         # compare models + evaluate vs the old LSTM benchmark

python -m fpl.run_week --team-id <your FPL team ID> --horizon 3
```
Without `--team-id`, `run_week.py` produces a build-from-scratch recommendation instead of
continuing an existing team. See `CLAUDE.md` for the full command reference, gameweek-numbering
convention, and the research/backtesting protocol.
